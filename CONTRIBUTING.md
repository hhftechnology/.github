# Contributing to HHF Technology projects

Thanks for helping! A few ground rules that apply to every hhftechnology repository unless it has its own CONTRIBUTING file.

## Where things go
- **Questions, help, ideas:** the [HHF forum](https://forum.hhf.technology). Every project has its own category, and GitHub issues are mirrored there, so the discussion lives in one place.
- **Bugs:** open a GitHub issue with steps to reproduce, the version, and logs. A forum topic is created for it automatically; the fix itself is tracked on GitHub.
- **Security issues:** never in public. Follow [SECURITY.md](https://github.com/hhftechnology/.github/blob/main/SECURITY.md).

## Pull requests
1. Open or find an issue first for anything bigger than a typo, so we can agree on the approach.
2. Fork, create a branch from the repository's **`dev` branch if it has one**, otherwise from the default branch.
3. Keep PRs focused; explain *what* and *why*; link the issue (`Fixes #123`).
4. Make sure the project builds and its tests pass. Don't commit secrets, `.env` files or real hostnames.
5. Target the **`dev`** branch where it exists. Maintainers merge releases into the default branch.

## Code of conduct
Be kind and constructive. The [forum guidelines](https://forum.hhf.technology/c/general/forum-guidelines/10) apply on GitHub too.
